# SOSD 키 검색 프로그램

SOSD 데이터셋(정렬된 uint32 키 2억 개, 약 800MB)에서 입력한 키의 위치를 찾는 프로그램입니다.
데이터를 메모리에 올리지 않고, 보간 탐색으로 필요한 4KB 블록만 파일에서 읽습니다.

## 1. 빌드

- 필요: Windows 10 이상, Visual Studio 2022 ("C++를 사용한 데스크톱 개발" 워크로드, 툴셋 v143)
  - VS 2026만 설치되어 있으면 "프로젝트 대상 변경" 창이 뜹니다. 확인을 누르면 됩니다. 단, 이 변경은 커밋하지 않습니다.
- `SosdSearch.sln`을 열고 **Release / x64**로 솔루션 빌드
- 실행 파일은 `build/x64/Release/`에 생깁니다.

| 프로젝트 | 위치 | 역할 | 제출물 |
|---|---|---|---|
| SosdSearch | `src/` | 본 프로그램 | O |
| GenData | `tools/` | 예시 데이터 생성 | X |
| DataCheck | `tools/` | 데이터 확인 (크기, 정렬, 중복, 간격) | X |
| VerifySearch | `tools/` | 정확성 검증 | X |
| Bench | `tools/` | 탐색 방법별 성능 측정 | X |
| JobLauncher | `tools/` | 512MB 메모리 제한 실행 | X |
| StructureCompare | `experiments/` | 해시·map·AVL 비교 실험 | X |

아래 명령은 모두 `CODE` 폴더에서 실행합니다. (`build\x64\Release\` 생략 표기)

## 2. 데이터 준비

데이터 파일은 Git에 올리지 않습니다. 실제 SOSD 파일이 있으면 `data/`에 넣고,
없으면 예시 데이터를 직접 만듭니다. 시드가 고정되어 있어 **누가 만들어도 같은 파일**이 나옵니다.

```
mkdir data
GenData.exe data            ← 균등 분포 4개 (약 25초, 1.6GB)
GenData.exe data skewed     ← 폴백 시험용 치우친 분포 1개 (4MB)
```

같은 파일이 만들어졌는지 `DataCheck.exe data\<파일>`로 확인합니다. 아래 값과 같아야 합니다.

| 파일 | 키 개수 | 첫 키 | 마지막 키 | 간격 최소 / 평균 / 최대 |
|---|---|---|---|---|
| gen_uniform_dense_10K_uint32 | 10,000 | 1000000 | 1010099 | 1 / 1.01 / 2 |
| gen_uniform_sparse_10K_uint32 | 10,000 | 1035322 | 4294684495 | 33 / 429407.86 / 4070327 |
| gen_uniform_dense_200M_uint32 | 200,000,000 | 1000000 | 202999999 | 1 / 1.01 / 5 |
| gen_uniform_sparse_200M_uint32 | 200,000,000 | 21 | 4294967291 | 1 / 21.47 / 403 |
| gen_skewed_1M_uint32 | 1,000,000 | 1000 | 4001000999 | 1 / 4001.00 / 32001 |

## 3. 실행

```
SosdSearch.exe <데이터 파일> [--no-buffering] [--binary | --index K]
```

- 쿼리 키는 **한 줄에 공백으로 구분**해 입력합니다. 개수는 자유입니다.
- 위치는 **0부터** 셉니다. 키가 없으면 "없음"을 출력합니다.
- 입력을 마친 뒤부터 시간을 잽니다. (빌드 시간 + 검색 시간, 타이핑 시간 제외)

| 옵션 | 의미 |
|---|---|
| (없음) | 보간 탐색 + 이분 탐색 폴백 (본안) |
| `--binary` | 파일 위 이분 탐색 (기준선, 비교용) |
| `--index K` | 샘플 K개 희소 인덱스 + 보간 탐색 (실험용) |
| `--no-buffering` | OS 파일 캐시를 거치지 않고 디스크에서 직접 읽음 (측정용) |

예시 (dense 2억, 존재 3개 + 미존재 2개):

```
SosdSearch.exe data\gen_uniform_dense_200M_uint32 --no-buffering
> 1000000 125691612 202999999 125691657 203000000
```

## 4. 검증과 측정

| 명령 | 내용 |
|---|---|
| `VerifySearch.exe <파일> [쿼리 수]` | 모든 탐색기의 결과를 파일에서 직접 읽은 정답과 비교. 마지막 줄이 "모두 통과"여야 함 |
| `Bench.exe <파일> [반복 수]` | 방법별 빌드·검색 시간(OS 캐시 없이, 반복 중앙값)과 쿼리당 블록 읽기 |
| `JobLauncher.exe [--limit-mb 512] <프로그램> [인자...]` | 512MB 제한을 걸고 실행, 최대 메모리 사용량 출력 |
| `StructureCompare.exe <파일> <N> <array\|hash\|map\|avl>` | 데이터를 메모리에 올리는 자료구조의 구축 시간·메모리 측정 |
| `StructureCompare.exe <파일> fullread` | 파일 전체 순차 읽기 시간 |

예: `JobLauncher.exe build\x64\Release\SosdSearch.exe data\gen_uniform_sparse_200M_uint32`

## 5. 결과를 비교할 때 지킬 것

- **블록 읽기 횟수**는 어느 PC에서나 같습니다. 서로 다른 PC끼리는 이 값으로 비교합니다.
- **시간**은 PC(특히 SSD) 성능에 따라 다릅니다. 시간은 **같은 PC에서 측정한 값끼리만** 비교합니다.
- 시간을 비교할 때는 OS 캐시 영향을 없애기 위해 `--no-buffering`을 쓰거나 `Bench.exe`를 씁니다.
  (캐시를 쓰면 두 번째 실행부터 디스크를 읽지 않아 빨라 보입니다.)
- 파일을 처음 열 때는 백신·OneDrive 검사로 수십 ms가 더 걸릴 수 있습니다. 첫 실행은 버리고 여러 번 재서 중앙값을 씁니다.
- 측정 조건(PC, 캐시 사용 여부, 반복 횟수)을 결과와 함께 적습니다.

## 6. 참고 결과 (작성자 PC, 예시 데이터)

| 방법 | 쿼리당 블록 읽기 (dense / sparse) | 쿼리 5개 합계 (OS 캐시 없이) |
|---|---|---|
| 이분 탐색 | 17.8 / 17.8회 | 약 6.7 / 7.9 ms |
| **보간 탐색 (본안)** | **1.4 / 2.3회** | **약 1.0 / 1.0 ms** |
| 희소 인덱스 K=16 | 1.15 / 2.11회 | 약 1.6 / 2.1 ms |

512MB 제한에서 본 프로그램의 최대 메모리 사용량은 약 1MB입니다.
